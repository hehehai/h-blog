# Sandpack 遥测报错调查与修复边界

## 当前状态

2026-10-12：调查完成，**尚未消除第三方遥测请求**。没有修改沙盒运行行为、屏蔽控制台、
拦截 fetch 或执行部署。询问实现方案后未收到选择，未将未答复视为授权。
此前浏览器回归发现的六类站内问题已修复；本记录只讨论剩余的第三方遥测错误。

## 已确认的来源

当前安装版本为 sandpack-react 2.20.0、sandpack-client 2.19.8。

| 请求 | 来源 | 本站的控制范围 |
| --- | --- | --- |
| `*.sandpack-static-server.codesandbox.io/cdn-cgi/rum` | 静态示例的第三方预览来源；此前浏览器记录为 404 | 本站不能修改该来源的响应、服务配置或内部脚本 |
| `col.csbops.io/data/sandpack` | 运行时 bundler 的 `persistMeasurements`；此前部分请求连接关闭 | 请求由远端 iframe 中的运行时代码发起，不是博客服务器函数 |

检查了安装包的 ClientOptions / SandpackInternalOptions 类型及运行时代码：

- 公开选项包含 bundlerURL、logLevel、externalResources 等，没有 disableTelemetry 选项。
- 运行时收集器在内部 `window._env_.IS_ONPREM === "true"` 时跳过该测量请求。
  这是运行环境内部标志，不是 SDK 提供的遥测开关；不应在博客中冒充部署模式或依赖跨域注入来关闭它。
- Static client 使用独立的 `static-browser-server` 预览协议，不能假设换一个普通静态资源 URL 就能兼容。
- 包内可自托管的 sandpack 运行时资源约 65 MiB；只复制这些资源也不能证明所有静态模板已兼容。

本轮结论来自安装包源码和公开文档；未伪造一次新的浏览器复测通过记录。
原始浏览器结果仍以 [浏览器回归记录](browser-regression.md) 为准。

## 不采用的“修复”

- 不设置 logLevel=None 或清空控制台来宣称网络错误消失。
- 不覆盖全局 fetch/sendBeacon、伪造成功响应或在测试中阻断请求后宣称修好。
- 不通过默认关闭全部演示、删除预览来掩盖问题。
- 不把可执行用户编辑代码的运行时直接部署到博客同域。
- 不仅在 localhost 不同端口测试后就声称生产 Cookie 隔离安全：端口不隔离 Cookie。

## 可实施的方案

### 保留可编辑沙盒：独立来源自托管

官方支持通过 bundlerURL 自托管运行时，参见
[Hosting the Bundler](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)。

实施前需确认采用此方案及生产隔离来源。执行步骤：

1. 固定运行时版本、保留许可证并记录文件校验值；对遥测行为做明确、可审阅的配置或源码修正。
2. 使用与博客隔离的运行来源，核对 DOM、存储、Cookie、CORS、Service Worker 范围和消息来源校验。
   不复用带有博客敏感 Cookie 的来源或 Cookie 域。
3. 单独处理三个 static 示例的预览协议：自托管兼容服务，或明确迁移到经验证的运行模板。
   不能只对 React/Vue 配置 bundlerURL 就认定全部完成。
4. 在本地隔离来源验证 25 个预览、编辑更新、资源路径、重试及运行时真实错误反馈。
5. 记录网络请求，确认不再请求上述遥测端点，同时不隐藏编译和运行错误。
6. 获得明确的域名/账户及部署授权后，部署独立运行环境，再接入博客并验收。

代价是新增资源托管、版本维护及隔离配置。不能只为消除日志而牺牲运行安全。

### 不再需要在线编辑：改为站内演示

移除第三方可编辑沙盒，以站内组件展示交互和代码。这样可以移除对应运行时和遥测依赖，
但会改变目前的在线编辑能力，需要明确接受这项产品取舍。

### 继续使用官方服务

保留当前功能与真实错误记录，等待或推动上游修复。此选择不等于本站已经解决遥测问题；
创建上游 issue、PR 或执行远程操作仍须单独确认。
